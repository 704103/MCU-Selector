# 数据字典

## 1. 适用范围

本字典定义单片机选型工具的源数据格式。第一版以 STM32 为主，但字段设计保留多厂商扩展能力。

数据粒度为“一个完整订货型号一条记录”。例如 `STM32F103C8T6` 和 `STM32F103CBT6` 必须分别建立记录。

机器可读版本位于 `data/source/schema.json`，枚举值位于 `data/source/enums.json`。

## 2. 文件职责

| 文件 | 用途 |
| --- | --- |
| `manufacturers.csv` | 厂商基础信息 |
| `mcus.csv` | 型号、性能、存储、封装、常用外设和来源信息 |
| `mcu_features.csv` | 不适合直接增加主表列的扩展参数 |
| `enums.json` | 状态、架构和扩展参数的受控枚举 |
| `schema.json` | 字段类型、必填规则、单位和表之间的关联 |

`data/source/` 是唯一维护入口。网页使用的 JSON 和搜索索引由发布流程自动生成。

## 3. 主表规则

`mcus.csv` 的唯一业务键是 `manufacturer_id + part_number`。`mcu_id` 是内部稳定 ID，创建后不应修改。

`brand` 是产品品牌，例如 `STM32`、`APM32`，必须单独保存。`manufacturer_id` 表示实际制造商，品牌和制造商不混用，以支持同一制造商拥有多个产品品牌的情况。

主表字段分为以下几组：

- 基础信息：品牌、型号、系列、厂商和生命周期状态；
- 内核性能：架构、内核和最高频率；
- 存储资源：Flash、SRAM、EEPROM 和备用 RAM；
- 电气参数：供电范围、IO 电压和工作温度；
- 封装资源：封装、引脚数和 GPIO 数量；
- 常用外设：ADC、DAC、定时器、串口、SPI、I2C、CAN、USB 等；
- 数据来源：产品页、数据手册、核验日期和备注。

## 4. 官方表列合并规则

导入官方选型表时，单位和语义一致的列使用统一字段：

- `RAM（Kbytes）` 与 `SRAM（KB）` 合并为 `sram_kb`；
- `IO` 与 `I/Os` 合并为 `gpio_count`，`U(S)ART` 合并为 `uart_count + usart_count`，网页显示合计；
- 12/14/16 位 ADC 的单元数和通道数分别保留，网页同时提供 `ADC` 汇总列；
- USB 汇总保留在 `usb`，Device、FS HOST/OTG、HS OTG 分别保存；
- APM32 的 GPTMR、Advanced TMR、LPTMR 等与 STM32 的同语义定时器列合并；名称或功能不同的列新增独立字段；
- APM32 的 `QSPI` 与 STM32 的 `M-SPI` 分开保存，避免把不同接口误合并。

未出现在现有目录中的官方列，必须在 `schema.json`、导入脚本和网页列定义中同时增加，保证筛选、排序和 CSV 导出字段一致。

## 5. 缺失值规则

- 空值表示“尚未确认”或“来源未提供”；
- `0` 表示确认没有该资源或数量为零；
- `false` 表示确认不具备该功能；
- `true` 表示确认具备该功能；
- 不使用 `N/A`、`unknown`、`无`、`没有` 等自由文本代替空值。

## 6. 单位规则

- 频率使用 MHz；
- 容量使用 KB；
- 电压使用 V；
- 温度使用摄氏度；
- 日期使用 `YYYY-MM-DD`；
- 数值字段只保存数值，不把单位写入单元格；EEPROM 同时保存官方字节值和换算后的 KB 值，换算值可使用小数。

## 7. 数据质量要求

每条公开型号必须有官方产品页面、官方数据手册和最近核验日期。来源中的复杂规格可以保存在 `source_note` 或 `mcu_features.csv` 中，但用于筛选的常用字段必须保持为数字或布尔值。
